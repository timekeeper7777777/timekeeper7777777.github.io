> 本篇为 PortSwigger Web Security Academy「Authentication」章节的学习笔记，穿插我自己的实操注解。

## 认证是什么

认证是验证用户或客户端身份的过程。网站可能暴露给任何连接互联网的人，这使得稳健的认证机制成为有效网络安全的关键。

认证主要有三种类型：

- **你知道的东西**——密码或安全问题的答案，也称「知识因素」。
- **你拥有的东西**——手机或安全令牌等实物，也称「占有因素」。
- **你是或正在做的事**——生物识别或行为模式，也称「固有因素」。

**认证和授权的区别**：认证验证「你是谁」，授权验证「你能干什么」。认证通过之后，权限决定你能访问什么、能执行什么操作。

## 认证漏洞是怎么产生的

大多数认证机制中的漏洞主要通过两种方式出现：

1. 认证机制薄弱，无法有效防范暴力破解攻击。
2. 实现中的逻辑缺陷或编码不佳，使认证机制被完全绕过（「认证失效」）。

由于认证对安全至关重要，错误的认证逻辑很可能会让网站面临安全隐患。

## 暴力破解密码

高熵密码对单靠计算机来说很难破解，但我们可以利用对人类行为的了解，利用用户无意中引入系统的漏洞。

用户通常不会用随机字符组合创建强密码，而是取一个自己能记住的密码，试图撬棍硬塞进密码策略中：

- 不允许用 `mypassword`，就试 `Mypassword1!`
- 或者干脆 `Myp4$$w0rd`

在策略要求定期改密码的情况下，用户通常只需对首选密码做一些小的、可预测的更改：`Mypassword1!` → `Mypassword1?` → `Mypassword2!`。

这种对可能凭证和可预测模式的了解，意味着暴力破解攻击往往比单纯迭代所有字符组合更复杂，因此也更有效。

## 用户名枚举

用户名枚举指攻击者能够观察网站行为的变化，判断某个用户名是否有效。通常发生在登录页面（有效用户名+错误密码 vs 两者都错）或注册页面（用户名已被使用）。

这大大减少了暴力破解所需的时间和精力——攻击者能快速生成一份有效用户名的候选名单。

尝试暴力破解登录页面时，要特别注意以下差异：

**状态码**——大多数猜测都会失败，状态码理应相同。如果某次返回不同，强烈表明用户名正确。最佳实践是无论结果如何都返回相同状态码，但这一做法并不总被遵守。

**错误信息**——有时「用户名和密码都错」与「只有密码错」返回的信息不同。最佳实践是两种情况下使用相同、通用的信息，但有时会出现小的打字错误。即使渲染页面上不可见，只要有一个字符不对位，两条消息就会区分开。

**响应时间**——如果大多数请求响应时间相似，任何偏离都表明背后发生了其他事情。例如网站可能只在用户名有效时才检查密码，这一额外步骤会略微增加响应时间。

这个可能很微妙，但攻击者可以**输入过长的密码**来使处理时间明显更长，把延迟放大到可观测。

## 实操：先枚举，再爆破

我一开始的疑问是：为什么要这么干？一起爆破不就行了。

> 因为如果有好判断的用户或密码，效率高多了。

具体做法：在 Burp Intruder 的 Payloads 侧面板选 `Simple list`，添加候选用户名列表。在 **Settings → Grep - Extract** 中添加，高亮响应中的错误信息文本。攻击结束后会多出一列提取到的错误消息，用这一列排序，找那条**有细微不同**的——比如错误信息里有个拼写错误，不是完整句号，而是后方有空格。记下这个用户名。

然后把结果窗口关掉，回到 Intruder 标签页，插入刚识别的用户名，再爆破密码。

## 暴力破解防护的缺陷

两种最常见的防护：

- 多次登录失败后**锁定账户**
- 连续多次尝试后**阻断 IP**

两种都提供一定保护，但都不是刀枪不入，尤其是在采用有缺陷逻辑实现时。

**计数器可被重置**：某些实现中，如果 IP 所有者成功登录，失败次数计数器会重置。这意味着攻击者只需每隔几次尝试登录自己的账户，就能防止限制被触及。

> 因为每错 3 次就会封 IP，所以在连续登录错 3 次内，循环插入正确的账号和密码（且不能多线程，不然就容易直接错 3 次了）。

更有效果的是在 home 目录请求中添加 `X-Forwarded-For: 1.1.1.1`——很多防护是基于这个头判断来源 IP 的。

## 用响应时间确认用户名

关键在这里：

- **用户名不存在**：服务器第一步直接返回「用户名或密码错误」，根本不去查密码，响应非常快。
- **用户名存在但密码错误**：服务器要先查出真实密码、比对、再返回相同提示。这个「查询+比对」需要时间，响应会慢一点点。

所以为了拉大区别、方便确认，**把密码往多了写**——处理时间差异会被放大到可观测。
