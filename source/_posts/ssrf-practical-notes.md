## SSRF 是什么

服务器端请求伪造（Server-Side Request Forgery）是一种允许攻击者使服务器端应用程序向非预期位置发出请求的漏洞。

本来是你浏览器发请求；现在变成：**骗后端服务器帮你发网络请求**。

在典型的 SSRF 攻击中，攻击者可能使服务器连接到组织基础设施内仅内部的服务，或强制它连接任意外部系统，泄露敏感数据（如授权凭证）。

SSRF 本身不执行命令，但它可以帮你间接拿到命令执行权限。

## 为什么「来自本地的请求」被隐式信任

想象一个购物应用，允许用户查看某商品在某门店是否有库存。它通过前端 HTTP 请求把 URL 传给后端 API：

```http
POST /product/stock HTTP/1.0
Content-Type: application/x-www-form-urlencoded

stockApi=http://localhost/admin
```

服务器获取该 URL 内容并返回给用户。`/admin` 管理功能通常只对已认证用户开放，攻击者直接访问看不到什么。

**但如果请求来自本地机器，访问控制就被绕过了**——应用程序授予管理功能完全访问权限，因为请求似乎来自可信位置。

为什么会这样：

- 访问控制检查可能在应用服务器前方的其他组件中实现，回连服务器时检查被绕过。
- 出于灾难恢复目的，应用可能允许任何来自本地的用户免登录访问管理员权限（假设只有受信用户会直接从服务器访问）。
- 管理界面可能在主应用的不同端口上监听，用户无法直接访问。

这种信任关系常使 SSRF 成为关键漏洞。

## SSRF 对其他后端系统的攻击

应用服务器往往能与用户无法直接访问的后端系统通信，这些系统通常有不可路由的私有 IP，受网络拓扑保护所以防护较弱，且常包含无需认证即可访问的敏感功能。

```http
POST /product/stock HTTP/1.0

stockApi=http://192.168.0.68/admin
```

## 实战：内网侦察怎么做

在完全不知道内网结构的情况下，可以这样做。

### 1. 先看自己拿到了什么信息

通过 SSRF 访问云元数据服务：

```text
http://169.254.169.254/latest/meta-data/
```

获取内网 IP 段。或者通过报错信息、页面泄露的 IP 推断内网网段。

### 2. 扫网段存活主机

用 SSRF 扫 `http://192.168.1.1:80`、`192.168.1.2:80`…… 看哪个返回了页面内容。

如果有**响应时间差异**（存在的主机响应更快），也能判断存活。

### 3. 扫常见端口

发现某个 IP 活着后，扫它的常见端口：`192.168.1.100:22`、`:80`、`:443`、`:8080`、`:3306`、`:6379`……

看哪些端口返回 Banner 或错误信息，识别服务类型。

### 4. 针对性访问路径

确认是 Web 服务后，用 SSRF 访问 `/admin`、`/api`、`/manager` 等敏感路径。

**要在内网合理寻找自己所需要的信息。**

## 实操：用 Intruder 扫内网

访问产品，点击「检查库存」，在 Burp Suite 拦截请求，发送给 Burp Intruder。

更改参数后，高亮 IP 地址最后一个八位组，点击 **Add §**：

```text
stockApi=http://192.168.0.1:8080/admin§1§
```

在 Payloads 侧面板把类型改为 **Numbers**，分别在 From、To、Step 填 `1`、`255`、`1`。

开始攻击后，按响应长度或状态码排序，就能找出内网存活的主机。
